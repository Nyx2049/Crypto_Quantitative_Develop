# 板块调研提示词模板

> 用途：对一个产业、技术或投资板块进行结构化调研。每次使用时替换方括号中的内容，并将最终报告保存到本文件所在目录。

## 可直接复制的提示词

请联网深度调研 **[调研领域，例如：光产业/光学产业]**，形成一份帮助我从基础知识开始，快速理解产业结构、关键参与者、竞争格局和近期资本市场表现的中文报告。

### 1. 调研目标

请回答以下核心问题：

1. 这个领域解决什么现实问题？其产品或技术最终被用在哪里？
2. 领域内部可以拆成哪些主要区块？各区块的功能、技术特点、商业模式和进入壁垒是什么？
3. 产业链的上游、中游、下游分别是什么？哪些环节掌握核心利润、技术或供应链话语权？
4. 世界主要参与国家或地区有哪些？各自强项、短板及产业分工是什么？
5. 按国家或地区列出每个关键区块的龙头公司和第二梯队代表公司，并说明判断依据。
6. 当前行业处于什么发展阶段？未来 3～5 年的重要驱动因素、约束和可能的结构变化是什么？
7. 产业内外有影响力的人物是否公开讨论过该领域？其原始观点、发表时间、背景和后续验证情况如何？
8. 相关上市公司最近的股价表现如何？上涨或下跌主要对应哪些已证实事件，哪些只是市场推测？

### 2. 调研范围

- 研究对象：[填写具体领域或子领域]
- 地理范围：全球，重点覆盖 [中国、美国、日本、韩国、欧洲；可修改]
- 时间范围：优先采用最近 3 年资料；涉及产业历史、长期格局或基础技术时可适当追溯。
- 产业边界：介绍直接相关的原材料、核心设备、关键零部件、制造、系统集成和主要应用；不要无限延伸到关联很弱的宏观行业。
- 公司范围：上市与非上市公司都可纳入，但必须标明；不因为公司知名度高就默认其为龙头。
- 读者定位：具备基础商业和投资知识，但不是该领域的技术专家。

### 3. 基础知识讲解规则

报告开篇先建立理解该领域所需的最小知识框架，不假设读者已经懂行业术语：

- 说明典型产品由哪些核心部件或步骤组成，各部分分别做什么。
- 解释关键材料、关键器件、制造工艺、设备、性能指标和常见技术路线。
- 对首次出现的缩写给出中文名称和一句通俗解释，再说明其产业意义。
- 说明真正形成护城河的因素：核心技术、良率、成本、产能、客户认证、专利、供应链、生态或渠道；不要把“技术先进”直接等同于“商业壁垒高”。
- 说明不同技术路线之间是替代、互补还是面向不同场景，并列出各自优缺点。
- 以“光领域”为例，应解释光模块的主要组成、光芯片是什么、不同光芯片的作用、光模块关键性能指标、CPO 是什么，以及这些环节的技术难点和护城河。

### 4. 公司与国家分析规则

按国家或地区分类，再按产业链区块介绍公司。每家公司尽量说明：

- 公司名称、总部国家、上市状态及股票代码（如有）。
- 主要产品、所在产业链环节、核心客户或主要应用。
- 龙头或第二梯队的判断依据，例如市场份额、收入、出货量、产能、专利、技术代际、客户认证或行业影响力。
- 相比主要竞争者的优势、短板和不可替代性。
- 若不同指标对应不同第一名，应明确写成“按市场份额”“按收入”或“按技术能力”，不要给出模糊的统一排名。
- 若没有可靠数据证明第一和第二，不要强行排名；改为“主要代表公司”，并说明证据不足。
- 对每个重点区块提供一个结构化公司信息块，至少包括：区块、龙头公司、第二名或第二梯队公司、主要产品、主要客户/应用、已公开的核心供应商、排名依据和数据时间。
- 供应商关系必须有公司披露、供应商披露、监管文件或多方可靠报道支持；无法确认时写“未可靠披露”，不能根据行业常识硬配供应商。

建议格式：

```markdown
#### [产业区块]

- 龙头公司 → [公司]
- 第二梯队 → [公司]
- 主要产品 → [产品]
- 上游供应商 → [已核实供应商，或“未可靠披露”]
- 下游客户/应用 → [客户或应用]
- 排名依据 → [份额、收入、出货量、数据时间]
```

### 5. X、公开访谈与关键人物观点

- 在 X（原 Twitter）及公开演讲、访谈、播客、财报电话会、博客中，搜索该领域有长期跟踪能力或产业影响力的人物观点。
- 可重点搜索用户指定人物，例如“白毛女股神”、黄仁勋，以及该领域的企业高管、科学家、工程师、投资人和行业研究者；也要主动寻找更直接相关的人物，不能只搜名人。
- 优先引用人物本人账号、完整访谈、官方文字稿或视频；二手转述只能作为线索，不能代替原始来源。
- 对 X 账号先核实账号身份；若昵称存在重名、无法确认本人账号或原帖不可访问，应明确注明，不能猜测。
- 每条重要观点写明：人物及身份、发布时间、原话要点、涉及的公司/技术、观点所依据的事实、当前是否已被数据或事件部分验证。
- 将“产业判断”“公司评价”“明确提及或推荐公司”分开记录。没有明确说过“推荐”时，不得改写成公司推荐。
- 社交媒体观点用于发现线索和理解预期，不作为行业排名或投资结论的唯一证据。

建议格式：

```markdown
#### [人物或账号]

- 身份 → [身份及核实情况]
- 时间与渠道 → [日期，X/访谈/演讲等]
- 核心观点 → [摘要]
- 涉及公司/技术 → [对象]
- 当前验证情况 → [已验证/待验证/被证伪]
- 原始来源 → [链接]
```

### 6. 近期股价表现与市场映射

- 对报告中的重点上市公司，统计截至调研时点的近期表现，默认列出近 1 个月、3 个月、年初至今和近 1 年涨跌幅；数据不足时说明原因。
- 同时列出对应国家宽基指数和最接近的行业指数/ETF作为基准，区分公司自身表现与市场整体行情。
- 写明行情截止日期和时间、交易所、币种、复权口径及数据来源；跨市场比较时提醒交易日和汇率差异。
- 结合财报、订单、产品发布、政策、供需变化等已证实事件解释表现。无法证明因果关系时使用“同期发生”“市场普遍解读为”，不能直接写成确定原因。
- 将基本面进展、估值变化和市场情绪分开分析；不因短期上涨就认定产业逻辑成立，也不因短期下跌就认定技术失去价值。
- 如公司未上市，不编造股价；可补充最近一轮融资、估值或上市公司可比标的，并标明口径差异。

建议格式：

```markdown
#### [公司] · `[股票代码]`

- 市场与币种 → [交易所/币种]
- 截止价与时间 → [价格/时间]
- 区间表现 → 近 1 月 [%]；近 3 月 [%]；年初至今 [%]；近 1 年 [%]
- 对比基准 → [指数或 ETF，以及超额表现]
- 同期事件 → [已核实事件]
- 数据来源 → [链接]
```

### 7. 来源与事实要求

- 必须联网核实，不依赖过时记忆。
- 优先使用公司年报、投资者关系材料、政府和监管机构、行业协会、标准组织、学术论文及权威研究机构。
- 新闻和券商材料可用于补充近期变化，但关键数据尽量交叉验证。
- X 帖文、访谈和公开视频应链接到原帖、完整视频或官方文字稿；若只能找到可信转述，必须显著标明“未找到原始内容”。
- 股价与指数数据优先采用交易所、指数公司或可靠行情数据源，并记录数据截止时点。
- 所有可能随时间变化的关键事实、市场数据、公司排名和重大判断都附可点击来源。
- 区分“来源明确的事实”“基于多项证据的推断”“尚无可靠答案”。
- 遇到口径冲突时列出冲突原因，不要擅自拼成一个精确数字。
- 不大段复制原文；以归纳、比较和解释为主。

### 8. 报告结构

请按以下顺序输出：

1. **报告信息**：写明调研领域、生成时间（北京时间 UTC+8）、信息和行情截止时间、研究边界。
2. **执行摘要**：默认用 4～6 条结论说明该领域最重要的结构、竞争格局与近期变化；复杂领域最多 8 条，避免把摘要写成正文。
3. **零基础知识导读**：解释产品组成、关键部件/材料、核心指标、技术路线、常见缩写和护城河。
4. **领域定义与实际作用**：用通俗语言解释它解决什么问题、主要应用在哪里。
5. **产业地图**：列出主要区块，并用“上游 → 中游 → 下游”的分组信息块说明功能、产品、技术特点、进入壁垒和价值量。
6. **上下游结构**：说明直接上下游、关键基础设施、核心依赖和利润集中环节。
7. **龙头、第二梯队与供应商速览**：按产业区块分别展示公司、主要供应商及排名依据，使用缩进列表明确上下游关系。
8. **全球国家/地区格局**：逐个国家或地区分析其优势区块、产业基础、短板和政策环境。
9. **重点公司图谱**：按国家/地区和产业区块展开龙头、第二梯队、客户、供应商及竞争壁垒。
10. **关键人物与 X 观点**：呈现原始观点、时间、涉及公司/技术及后续验证，严格区分观点与事实。
11. **近期股价表现**：每家公司单独使用一个行情信息块，对比区间涨跌、行业/宽基基准、基本面事件、估值与情绪。
12. **关键技术与商业竞争点**：说明真正决定竞争力的技术、成本、产能、认证、渠道或生态。
13. **未来 3～5 年驱动与风险**：分别列出需求驱动、供给变化、技术替代、政策和周期风险。
14. **值得继续追踪的问题**：列出目前证据不足、存在争议或需要后续更新的事项。
15. **结论**：总结最有价值的环节、最强国家/公司及不应忽视的风险，但不直接给出买卖建议。

### 9. Markdown 排版与可读性规范（必须执行）

报告主要在 VS Code 的 Markdown 预览中阅读。完整保留有效内容与来源，不要为了“看起来简洁”删掉关键证据；通过层级、留白和信息分组提高可读性。

#### 9.1 页面结构

- 全文只使用一个一级标题 `#`；主要章节使用 `##`，章节内部使用 `###`，不要跳级。
- 标题下方先放简洁的报告信息引用块，统一列出研究范围、信息截止时间、行情截止时间和北京时间生成时间。
- 执行摘要后提供“阅读导航”目录，链接到主要章节，方便在长报告中跳转。
- 主要章节之间使用 `---` 分隔；不要在每个小标题之间都加分隔线。
- 每个主要章节开头优先使用一行引用块写出“本节结论”，随后再给证据和解释。
- 文末将完整来源清单放入可展开的 `<details>` 区域；正文中的关键事实仍保留就近链接。

#### 9.2 段落与列表

- 一个段落只表达一个主要观点，通常控制在 2～4 句；长逻辑拆成短段落或列表。
- 先写加粗的结论词，再展开证据，例如：`**行业景气已验证，但估值风险仍高。**`
- 三个及以上并列事项使用项目列表或编号列表，不要塞进一个长句。
- 操作建议、跟踪指标和待验证问题使用 Markdown 任务列表 `- [ ]`，便于后续更新。
- 中文、英文缩写和数字之间保持一致空格，例如 `CPO 进入量产阶段`、`近 3 年`、`800G 模块`。
- 首次出现的缩写采用“中文名称（英文缩写）”或“英文全称（缩写）”，后文只使用缩写。

#### 9.3 关系与对比信息

- 默认不使用 `| 字段 | 字段 |` 形式的 Markdown 管道表格。这类表格在 VS Code 源码视图和手机窄屏中难以阅读。
- 公司、人物、国家、产业环节和股票行情默认使用“加粗名称 + 缩进属性”的信息块。
- 关系字段统一使用箭头表达，例如：`上游供应商 → TSMC`、`下游应用 → AI 数据中心`。
- 产业链使用“上游 → 中游 → 下游”的章节顺序，并在每个主体下分别写产品、公司、客户和壁垒，不能把不同关系塞在同一行。
- 同一组信息的字段名称必须一致，例如所有公司都按“主要产品、上游供应商、下游客户、排名依据”排列。
- 只有在用户明确要求表格，并且不超过 4 列、每个单元格只有短词时，才允许使用 Markdown 表格。
- 不能为了取消表格而删除字段；应把原字段完整迁移到结构化信息块。

#### 9.4 链接与来源

- 来源链接数量不设上限。重要事实、排名、股价、人物发言和时效性判断必须保留可点击来源。
- 关键链接放在相关事实附近，不要让读者必须翻到文末才能判断证据。
- URL 很长或同一来源多次出现时，可使用 Markdown 引用式链接，例如正文写 `[NVIDIA][nvidia-cpo]`，在文末统一定义 URL。
- 链接排版只服务于阅读，不得以“链接太多”为理由删减来源或降低证据密度。
- 完整来源按“行业与技术、公司与财报、人物与政策、行情数据”等类别整理，避免一个无分类的超长列表。

```markdown

> **研究范围**：[...]  
> **信息截止**：[...]  
> **生成时间**：[...]（北京时间 UTC+8）

- **结论二。** 证据与意义。

```

#### 9.6 交付前排版检查

- 标题层级是否连续，目录链接是否能跳转。
- 执行摘要能否在一屏左右读完。
- 是否存在超过 4 句且可以拆分的长段落。
- 是否仍存在未经用户明确要求的 Markdown 管道表格。
- 公司、供应商、客户和应用之间是否使用清晰的缩进与箭头表达关系。
- 每个主要章节是否先给结论，再给证据和含义。
- 关键数字、排名、人物观点和近期变化是否有就近链接。
- 来源清单是否分类，固定免责声明是否保留。
- 在 VS Code 中使用 `Ctrl+Shift+V` 打开 Markdown 预览，确认表格、目录、折叠来源和中英文空格显示正常。

### 10. 表达方式

- 先说结论，再解释证据。
- 少用空泛形容词，多用可比较的指标和具体产品。
- 技术概念第一次出现时给出一句通俗解释。
- 默认使用结构化信息块和缩进列表；只有极少量、短字段的横向比较才使用表格。
- 不设最低或最高字数。篇幅服从领域复杂度和有效信息量：简单领域简短说明即可，复杂领域再按需展开。
- 优先保留能帮助理解、比较和决策的信息；删除重复结论、空泛背景、无证据判断和为了篇幅而填充的内容。
- 固定注明：**本报告用于产业研究，不构成投资建议。**

### 11. 文件要求

- 将报告保存为 Markdown 文件。
- 保存目录：`板块调研报告/`
- 文件名只使用中文主题和北京时间日期，格式：`[领域名称]调研报告_[YYYY年MM月DD日].md`
- 文件名不写小时和分钟；精确生成时间继续保留在报告正文的“报告信息”中。
- 示例：`光领域调研报告_2026年08月14日.md`
- 报告正文开头再次写明完整生成时间和资料截止时间，避免文件时间与数据时间混淆。
- 文末保留“主要来源”章节，列出报告实际引用的核心来源。

## 示例用法
