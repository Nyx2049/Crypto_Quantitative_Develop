# 公司分析提示词模板

> 用途：对一家上市或拟上市公司进行可复核的基本面研究。使用时替换方括号内容，并将成品保存在本目录，文件名使用 `公司名公司分析报告_YYYY年MM月DD日.md`。

## 可直接复制的提示词

请联网分析 **[公司名 / 股票代码]**，形成一份面向普通投资者、但经得起财务核对的中文公司报告。目标不是堆砌公司介绍，也不是给出机械买卖评级，而是回答：

1. 这家公司靠什么赚钱，行业位置是否真实？
2. 增长来自行业景气、份额提升、产品升级、并购还是扩产？证据处于量产、认证、送样还是规划阶段？
3. 利润和现金流是否跟得上收入，增长质量如何？
4. 当前股价已经计入了多少乐观预期，未来最关键的验证点是什么？

## 一、研究原则

- 优先使用年报、季报、交易所公告、招股书、投资者关系记录、公司官网及监管文件。
- 新闻、行情网站和券商材料只作补充；关键财务数字必须尽量回到公司原始披露。
- 把“公司披露”“第三方统计”“本报告推断”分开，不把公司宣传语直接当结论。
- 客户和供应商没有可靠披露时写“未可靠披露”，不得凭产业常识硬配名单。
- 对新业务使用证据等级：`已形成收入/批量供货` → `客户认证` → `送样/小批量` → `研发/规划`。
- 公司质量、行业景气和股票估值分开判断。好公司不等于任何价格都值得买，短期业绩下滑也不自动代表长期逻辑失效。
- 不使用模糊的“空间巨大”“前景广阔”作为核心论据；每个重要判断后写明可验证指标。

## 二、必须回答的问题

### 1. 一页结论

- 公司一句话定位。
- 最强的 2～3 个竞争优势。
- 当前最重要的增长引擎。
- 当前最主要的经营矛盾。
- 对股票的结论：估值偏低、合理、偏高或因信息不足无法判断；写清依据，不给强制买卖指令。

### 2. 商业模式

- 公司卖什么，卖给谁，客户为什么选择它。
- 收入、毛利和利润主要来自哪些产品、区域与应用。
- 订单模式、认证周期、定价权、回款和资本密集度。
- 周期品、成长品、平台型公司或项目型公司的属性。

### 3. 行业位置和竞争格局

- 对应产业链环节、全球及国内主要竞争者。
- 排名必须注明按收入、份额、出货、技术还是客户覆盖。
- 与 3～5 家可比公司比较：产品结构、客户、技术、盈利能力、资本开支和估值。
- 说明公司真正胜出的指标，也说明它弱于同行的部分。

### 4. 护城河

分别判断以下壁垒是否存在、能否转化为利润：

- 技术与工艺 → 是否有量产良率和客户验证，而不只是专利数量。
- 客户与认证 → 认证周期、供应商切换成本、客户集中度。
- 成本与规模 → 单位成本、稼动率、自动化、采购能力。
- 产品组合 → 是否能交叉销售、平滑周期或提高单客户价值。
- 全球产能 → 是否解决客户本地化和供应链安全需求。
- 管理与组织 → 扩产、海外工厂、新客户导入能否同时执行。

### 5. 财务质量

至少覆盖最近 3 个完整年度和最新季度；若篇幅有限，正文可突出最近两年，但底稿必须核对：

- 营业收入、归母净利润、扣非净利润及增速。
- 毛利率、净利率、扣非净利率和加权 ROE。
- 经营现金流、经营现金流/净利润。
- 资本开支与“经营现金流减资本开支”的自由现金流近似值。
- 应收账款、存货相对收入的变化。
- 有息负债、资产负债率、利息和汇率影响。
- 非经常性损益、政府补助、公允价值变动等对利润的影响。
- 季度趋势：收入、利润和利润率是否同向。

计算值要标注为“本报告按财报数据计算”，并保留公式口径。例如：

```text
综合毛利率 =（营业收入 - 营业成本）/ 营业收入
自由现金流近似值 = 经营活动现金流净额 - 购建固定资产、无形资产和其他长期资产支付的现金
```

### 6. 增长兑现

对每条增长线使用统一信息块：

```markdown
#### [增长业务]

- 当前阶段 → [规模收入 / 批量供货 / 认证 / 送样 / 规划]
- 已有证据 → [公告、客户认证、产能、收入等]
- 还缺什么 → [客户、良率、稼动率、利润率等]
- 兑现窗口 → [时间区间]
- 失败信号 → [可观察的反向指标]
```

新增产能必须说明预算、投产、爬坡、客户导入和折旧压力，不能把“投产”直接等同于“盈利”。

### 7. 管理层与治理

- 实际控制人、控股股东、管理层稳定性和持股。
- 股权激励目标、分红、回购、再融资、可转债、H/A 股发行等资本动作。
- 关联交易、担保、质押、少数股东权益和潜在利益冲突。
- 管理层过去承诺与实际兑现的匹配度；证据不足时不作人格判断。

### 8. 股价与估值

- 写明行情日期、股价、市值、近 1 月、年初至今和近 1 年表现。
- 至少使用市盈率、市销率或企业价值类指标中的适用口径；周期或资本密集公司同时参考净资产和现金流。
- 与直接可比公司比较估值，但先解释业务结构和增长差异。
- 使用情景法，不伪造精确目标价：
  - 乐观情景 → 需要哪些经营事实发生。
  - 基准情景 → 哪些指标正常兑现。
  - 压力情景 → 哪些因素导致盈利和估值同时收缩。
- 明确指出“当前价格隐含的预期”及下一次最可能改变预期的财报或事件。

## 三、报告结构

1. 报告信息与数据截止日。
2. 执行摘要。
3. 一句话结论和观察立场。
4. 公司与商业模式。
5. 收入结构和客户应用。
6. 行业位置、同行对比和护城河。
7. 财务质量与季度趋势。
8. 增长引擎和产能兑现。
9. 管理层、股权与资本动作。
10. 股价、估值与市场预期。
11. 催化剂、风险和证伪条件。
12. 未来四个季度跟踪清单。
13. 结论。
14. 完整来源。

## 四、Markdown 排版规范

- 全文只用一个一级标题 `#`；主要章节用 `##`，内部用 `###`，不跳级。
- 默认不使用 Markdown 管道表格。手机和 VS Code 源码视图中，表格很难阅读。
- 公司、财务、竞争者、催化剂使用“加粗标题 + 缩进属性”的信息块。
- 关系字段统一使用箭头：`核心产品 →`、`主要客户 →`、`验证指标 →`。
- 每个主要章节开头放一行引用块概括本节结论。
- 重要数字后就近放可点击来源；文末再用 `<details>` 汇总来源。
- 段落保持短小，先给结论，再给证据；三个以上并列项改用列表。
- 需要持续更新的项目使用任务列表 `- [ ]`。
- 文件名中的日期只到年月日，不添加时分秒。

## 六、质量检查

交付前逐项检查：

- [ ] 报告是否把“公司好”与“股票便宜”分开？
- [ ] 是否至少使用一份最新定期报告和一份年度报告？
- [ ] 新业务是否标注证据阶段，没有把认证、送样写成收入？
- [ ] 财务计算是否可复核，合并口径与母公司口径没有混用？
- [ ] 是否讨论毛利率、现金流、资本开支、存货、应收和负债，而不只看收入利润？
- [ ] 客户和供应商是否有可靠来源？
- [ ] 排名和市占率是否注明来源、口径和时间？
- [ ] 估值数据是否注明行情截止日？
- [ ] 是否写出催化剂、风险、证伪条件和季度跟踪项？
- [ ] 是否避免直接买卖指令，并保留固定免责声明？

本模板可以随研究目标调整，不是写死的限制。
