# 零度雷达 ZeroSlope

一个专注于币安 USDⓈ-M 永续合约的 4H EMA99 趋势筛选器。

零度雷达不会给出交易指令。它从高流动性合约中找出 EMA99 角度最接近水平、趋势最陡、正在加速或可能改变方向的标的，供交易者再到 Binance 或 Hyperliquid 人工确认。

线上地址：

<https://binance-ema99-scanner.binance-ema99-scanner.workers.dev/>

2026-09-09 已在当前授权的 Cloudflare 账号重新部署。旧地址不再作为本仓库的更新目标。持仓保存在浏览器对应网站的数据中；更换网址不会自动迁移持仓，可在旧站点点击“分享持仓”，将分享链接的域名换成上述新域名并保留完整 `#positions=...` 片段，再打开导入。

## 候选模块

当前候选策略名为 **EMA99 零度筛选器 2.0**。

### 2.0：宽筛选，分状态，不强等 4H 回踩

这套策略仍然在做 **EMA99 右侧反转候选**，不是追涨加速策略：先观察长期曲线走平，再确认 Angle10 反向穿过零度。1H 只补充穿零之后的价格行为，不改成用 1H EMA99 选股。

- **近零 Top 20**：保留原来的宽候选列表，按 `|Angle10|` 升序，不要求每个标的都已转向。
- **72h 留观**：同一扫描池内，最近 72 小时出现有效穿零的标的即使离开 Top 20，也附加在列表末尾。超时不再附加；如果仍在 Top 20，则回到普通观察。
- **自动回看**：每次打开或扫描，请求已收盘 1H，重建信号后的回踩过程。不必网页一直开着；但这不是后台监控，也不会记录两次扫描之间的每个 tick。
- **不因回踩缩紧结构参考**：候选止损固定为穿零发生时的 60 根已收盘 4H 结构极值外 0.3%，不会每次重新选一个更近的小时线低点/高点。持仓退出策略的 ATR 保护价仍独立运行。

各状态的具体含义：

| 状态            | 判断口径                                                                       |
| --------------- | ------------------------------------------------------------------------------ |
| 零度观察        | 最近 72h 没有满足前段曲线确认的反向穿零事件                                    |
| 刚刚转向        | 已有 4H 穿零，但尚无信号之后的已收盘 1H                                        |
| 等待回踩        | 信号后 1H 数据完整，尚未看到回踩收回                                           |
| 回踩中 · 待收回 | 曾触及当时可知的 4H EMA99 ±0.35%，尚未收回候选一侧                             |
| 回踩已收回      | 先在候选一侧，再触及均线邻域，并在同一根或后续已收盘 1H 收回该侧；现价仍在该侧 |
| 已走远 · 不追   | 现价沿候选方向距当前 4H EMA99 超过 3%；这是提示，不删除候选                    |
| 转向/结构失效   | 穿零后已收盘 4H Angle10 回到原侧，或后续 1H 高低价/现价触及固定结构参考价      |
| 数据待补齐      | 1H 请求失败、缺根或过期；不冒充“等待回踩”，4H 候选仍显示                       |

穿零必须是相邻两次 **已收盘 4H Angle10** 从非正转正或从非负转负，且在穿零时确认前段反方向曲线。不会把“今天角度为正”当成“今天刚穿零”。同一事件一旦失效，即使价格后来回到盈利侧也不会复活；需要新的有效事件。

小时线引用 **该小时开盘前已收盘的 4H EMA99**，避免偷看后来数据。1H OHLC 不能完整还原盘中路径，同根“触及并收回”只能说明小时级形态，不能证明可以按某个价成交。72h 留观由新行情重建，不是持久化自选股；离开配置扫描池、停止交易或行情失败的标的无法保证继续覆盖。

这些阈值是透明的初始规则，**未经本策略完整回测，不代表已验证的胜率或更小回撤**。真实反转仍可能反复扫损；放宽止损会增加单笔损失幅度，不能靠“最终总会回来”替代风险预算。

策略使用最近 10 根 4H K线对应的 EMA99 角度：

```text
SlopePctPerBar = [(EMA_now / EMA_10_bars_ago) - 1] × 100 / 10
Angle10 = atan(SlopePctPerBar) × 180 / π
```

先按照 `|Angle10|` 从小到大排列。正角度和负角度一起比较，越接近 `0°` 越靠前：

```text
+0.01°
-0.03°
+0.06°
-0.08°
```

核心思路是用较慢的 99 根 4H 均线寻找右侧反转候选：

- 前一段 EMA99 明显下跌，当前 Angle10 穿到 `0°` 上方，标记为“做多”候选。
- 前一段 EMA99 明显上涨，当前 Angle10 穿到 `0°` 下方，标记为“做空”候选。
- 尚未形成与前趋势相反的零度穿越时，标记为“观望”。

前一段趋势不再只看固定窗口的角度符号，而会进行“有效曲线确认”。当前规则检查截至 10 根 K线之前的 24 根 EMA99：方向一致率至少 75%，平均角度至少 `0.1°`，逐根峰值角度至少 `0.12°`，EMA99 净位移至少 `0.04%`，并限制斜率总变差相对峰值的比例，过滤长期趋势中的短暂反向波纹和来回抖动。只有前段曲线通过确认且当前 Angle10 反向穿越 `0°`，才输出做多或做空候选。

2.0 候选参考止损使用穿零当时最近 60 根已收盘 4H K线的结构极值：多头放在最低价下方 0.3%，空头放在最高价上方 0.3%。页面显示距现价百分比，超过 5% 提示偏远；它是粗略结构失效参考，不是交易所挂单，也不保证是人工观察到的精确拐点。

## 页面内容

- 资产显示：以 `BTC`、`NVDA`、`XAU` 等标准资产名为主，候选卡片辅以完整合约名，避免混淆 USDT/USDC。现价为 Mark Price，24h 涨跌幅来自官方 ticker（最近 24 小时成交价变化，并非昨日零点或 Mark Price 变化）；上涨绿色、下跌红色，缺失显示横杠。
- 固定关注：比特币、QQQ、黄金、原油和韩国市场 ETF 独立展示在第一排。
- 已持有仓位：可从策略列表添加，也可手动输入 `BNB`、`BNBUSDT` 等币对简称；记录多空方向、开仓价和结构止损，并由独立的“持仓退出策略 1.0”生成分批平仓建议。界面只显示基础标的简称，例如 `BTCUSDT`、`BTCUSDC` 均显示为 `BTC`，内部仍保留完整合约名用于行情匹配与同步。
- 扫描池：覆盖大市值加密资产以及大市值/热门美股代币，并保留固定关注和当前持仓所需行情。当前已持有的基础标的会从候选区排除，例如持有 `ZECUSDC` 时也会排除 `ZECUSDT`；平仓后下一轮会恢复参与候选计算。
- EMA99 零度筛选器 2.0：独立卡片显示现价、24h 涨跌、真实 EMA99 迷你曲线、候选方向、回踩状态和结构参考；可按多头、空头、回踩收回筛选或搜索资产。先显示近零 20 个，再附加同池 72h 留观。成交额只作为流动性参考。
- 日线 EMA99 背景：为候选和持仓标记“初步牛市背景、初步熊市背景、日线中性、日线转折/分化”。不同标的的牛熊周期并不同步，因此当前标签只是单标的日线 EMA99 的初步描述，不参与候选排序、推荐方向或平仓比例。
- 趋势观察：最陡上涨、最陡下跌、加速上涨、加速下降和可能转向。
- 完整扫描表：默认折叠，展开后按 Angle10 距离零度排序，可点击表头重新排序；趋势分组和诊断也默认折叠。
- 市场状态：统计 EMA99 方向、价格相对 EMA99 的位置和趋势扩散程度。
- 异常记录：单个合约失败不会中断整次扫描。

## 数据与计算口径

- 数据只来自 Binance 官方 USDⓈ-M Futures 公共 API。
- 成交额排序同时读取 Binance 官方现货 24 小时行情，将同一基础资产的 USDT、USDC 现货 Quote Volume 与合约 Quote Volume 相加。现货接口不可用时页面会明确显示“仅合约”，不会伪造现货数据。
- 股票现货代币和 TradFi 合约按底层股票合并，例如 `NVDABUSDT` 的现货成交额会归入 `NVDAUSDT`，`TSLABUSDT` 会归入 `TSLAUSDT`；候选去重与持仓排除也使用同一映射。
- 主地址为 `fapi.binance.com`，失败时依次尝试 `fapi1` 至 `fapi4` 官方备用地址。浏览器单请求 9 秒超时；遇到 418/429 停止该请求的节点轮询。错误保留接口路径、实际 HTTP 状态或网络/CORS/超时信息。
- 不需要 Binance API Key，不使用数据库或第三方行情。
- 扫描 `USDT + PERPETUAL + TRADING` 合约，排除稳定币、杠杆代币和交割合约。
- 大市值加密资产与大市值/热门美股代币全部参与计算，候选区显示近零前 20，加上 72h 穿零留观；不是此前历史版本的币圈 10 + 股票 10 配额。
- 每个合约请求 320 根 4H K线，至少 150 根有效已收盘 K线；检查连续性和最新收盘时间，过期数据跳过。扫描开始时间统一作为 4H/1H 截止时间，跨收盘边界时不会混入未来一根。
- 当前价格使用 Mark Price。
- Open Interest 名义价值按 `Open Interest × Mark Price` 估算。
- 页面时间统一显示为北京时间 UTC+8。

EMA99 使用前 99 个收盘价的简单平均值作为初始值，之后按标准 EMA 递推：

```text
α = 2 / (99 + 1)
EMA_t = Close_t × α + EMA_(t-1) × (1 - α)
```

## 当前架构

Cloudflare Worker 负责提供网页。每次打开或刷新网页会自动扫描一次，也可以点击“立即扫描”手动刷新。浏览器直接请求 Binance 官方 API，并在本地完成 EMA99 和角度计算。

采用浏览器直连是因为 Binance 会对部分 Cloudflare Worker 出口节点返回 `403 Forbidden`。这种结构具有以下特点：

- 不需要自建服务器，也不需要电脑长期在线。
- Cloudflare 只负责托管轻量页面。
- 行情不会经过自建中转服务。
- 手机或电脑所在网络必须能够访问 `fapi.binance.com`。
- `/api/scan` 保留为旧版服务端基础指标接口，不包含浏览器 2.0 的候选生命周期、TradFi 扩展或本地持仓；在 Binance 拒绝 Cloudflare 出口的区域可能返回 403 汇总错误。不要当作网页结果的完整镜像。

页面先展示 4H 扫描结果，再并行补齐小时线状态与日线背景。补充失败不抹掉已有候选；整轮失败时保留旧快照并明确提示不是当前行情。持仓与候选复用同一轮的 1H 请求，固定关注的 24h 变化复用已经取得的 ticker。

已持有仓位使用浏览器 `localStorage` 保存在当前设备，不上传服务器。普通刷新和关闭页面不会丢失；清除网站数据、无痕模式、换浏览器或换设备时不会自动同步。

持仓区域提供“分享持仓”：

- “分享持仓”会生成只包含持仓配置的链接。另一台设备打开后会直接覆盖本机持仓并自动扫描，不再弹出确认框；导入结果会显示在持仓区域。
- 分享数据放在 URL 的 `#positions=...` 片段中，浏览器不会把该片段发送给 Cloudflare Worker。拿到完整链接的人仍可读取仓位，请只通过可信渠道分享。
- 链接中的配置包含版本、导出时间以及币对、方向、开仓价和结构止损价，不包含行情扫描数据。
- 打开链接时会校验配置版本及全部仓位字段，然后用链接内容完整替换当前设备的持仓，使不同客户端保持一致。

手动新增持仓时可以只输入基础币简称，例如 `BNB`。扫描会优先寻找 `BNBUSDT`，不存在时再寻找 `BNBUSDC`；保存后会立即扫描并显示实际匹配到的交易对。

## 持仓退出策略 1.0

退出策略位于独立的 [`src/exit-strategy.ts`](src/exit-strategy.ts)，与候选模块隔离。默认部署会启用；如果某台服务器不需要平仓功能，将 Wrangler 变量 `ENABLE_EXIT_STRATEGY` 设为 `"false"` 即可隐藏退出建议，持仓记录仍可使用。

页面输出 `继续持有` 或 `建议平仓 25% / 50% / 100%`。判断依据包括：

- 只对当前已持仓标的额外扫描 1H EMA99。1H 连续两根收盘处于错误一侧，或 1H Angle5 与 Angle10 同时反向时，如果仓位已有浮盈，可提前建议平仓 25%。1H 信号不会单独触发 50% 或 100% 平仓，也不会在浮亏时强制止损。
- 用户填写的结构止损、网页追踪以来的最佳价格，以及只朝盈利方向收紧的 ATR 保护价。
- Angle5 短期反向、Angle10 中期反向、连续两根 4H 收盘处于 EMA99 错误一侧，以及经过曲线确认的反方向候选。
- ATR14 作为保护距离；ATR7 / ATR28 用于比较近期和基准波动率。ATR 不判断方向，因此不会单独触发平仓，只会在已有盈利并同时出现趋势减弱时提高保护强度。
- 达到约 `1R` 后保护价至少推进到开仓价；达到约 `1.5R` 后开始使用 ATR 跟踪。近期波动显著放大时，跟踪距离会更谨慎。

网页会在本地保存开始追踪时间、最后一根已收盘行情时间、追踪以来的最佳价格和当前保护价。开始追踪时间只是网页首次记录该仓位的时间，不会冒充交易平台的真实开仓时间；手动同步延迟不会被错误解释为持仓时长。

分享链接配置已升级为版本 2，会同步上述追踪状态，使手机与电脑沿用同一保护价；旧版版本 1 链接仍能导入并自动补齐追踪字段。

分批平仓比例是透明规则的输出，不是自动交易指令或投资建议。页面不会代替用户在交易平台执行平仓。

退出策略暂不使用 1H EMA50，避免 EMA50、EMA99 与两个周期同时产生过多相互冲突的信号。当前职责边界是：`1H EMA99` 负责提前预警和保护已有利润，`4H EMA99` 负责判断原持仓逻辑是否失效以及是否需要平仓 50%～100%。

日线 EMA99 只作为背景标签。日线与 4H 冲突时，页面会如实展示熊市背景反弹或牛市背景回调所处的大环境，但不会过滤 4H 候选，也不会改变退出策略计算。这样可以保留完整的 4H 波段，避免等待日线 EMA99 转向而错过一段已经走完的行情。

后续背景模型应优先加入每个标的自身的历史分位和周线结构，解决不同币种、股票和商品牛熊周期不同步的问题。新闻与事件信息具有来源、发布时间和市场消化速度不稳定等问题，适合作为可追溯的人工背景备注，不应未经验证直接改变自动交易建议。

## 候选模块扩展约定

“候选模块”是多个选股/选币策略的容器，不是某一个策略的名称。

- 每张候选卡片使用具体策略名和版本号命名，例如 `EMA99 零度筛选器 2.0`。
- 新策略沿用现有候选卡片的视觉结构和交互方式，并按照页面顺序向下添加。
- 每个策略应写清排序或筛选口径，只负责生成候选标的，不描述为确定交易信号。
- 新增策略时尽量复用扫描结果，避免为了同一份行情重复请求 Binance API。
- 同步补充测试和本 README，确保其他维护者能理解策略来源和版本差异。
- 这是一项可演进的项目约定，不是不可修改的硬性限制；产品结构变化时可以连同文档和测试一起调整。

## 固定关注配置

维护入口：`src/page.ts` 负责现有扫描和持仓 UI；`src/candidate-strategy.ts` 是 2.0 事件/回踩纯函数；`src/dashboard.ts` 集中维护新版视觉和候选卡片。候选代码通过函数序列化共享给浏览器，单元测试和浏览器实际执行相同实现。

可调参数：`findTurnEvent` 的 `watchHours=72`；`evaluateRetest` 的 `touchPct=0.35`、`extendedPct=3`。结构窗口 60 根、缓冲 0.3% 在 `findTurnEvent` 中；修改时同步更新文案、测试与本说明。1H 候选使用 4H EMA 基准，持仓退出仍使用自己的 1H EMA99，二者不要混淆。

固定合约集中配置在 [`src/page.ts`](src/page.ts)：

```js
const PINNED_PAIRS = [
  { label: "比特币", symbol: "BTCUSDT" },
  { label: "纳指 QQQ", symbol: "QQQUSDT" },
  { label: "黄金", symbol: "XAUUSDT" },
  { label: "原油", symbol: "CLUSDT" },
  { label: "韩指 EWY", symbol: "EWYUSDT" },
];
```

固定 TradFi 合约不依赖普通币的批量行情集合，而是分别请求指定符号的：

- `/fapi/v1/ticker/24hr`
- `/fapi/v1/premiumIndex`
- `/fapi/v1/klines`
- `/fapi/v1/openInterest`

修改 `label` 和 `symbol` 后重新部署即可更换第一排合约。不存在或不可用的合约会明确显示错误，不会生成虚假数据。

## 故障排查

### 网页打不开

部分网络可能无法直接访问 `workers.dev`。可以切换网络、使用代理，或为 Worker 绑定自己的 Cloudflare 域名。

### 所有 Binance 地址均失败

查看页面展示的实际状态：

- `403`：Binance 拒绝当前出口或所在地区访问。
- `418` / `429`：请求频率过高，稍后重试。
- 网络或 CORS 错误：当前浏览器网络无法直连 Binance API。

系统不会静默切换到第三方行情。

### 单个合约没有数据

可能是合约尚未积累 150 根已收盘 4H K线、已经停止交易，或该符号不在 Binance USDⓈ-M 永续池。其他合约仍会继续扫描。
